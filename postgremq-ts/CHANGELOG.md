## [0.5.0](https://github.com/postgremq/postgremq/compare/npm/v0.4.0...npm/v0.5.0) (2026-10-24)


### ⚠ BREAKING CHANGES

* **go,cli,ts,rs:** migration errors are typed in every client, and a recorded schema version below the latest that is none of the migrations is refused. Go: postgremq-go no longer depends on golang-migrate or testcontainers-go. Migrate returns *MigrationError (errors.Is ErrMigrationFailed; the *pgconn.PgError stays in the chain) instead of a wrapped golang-migrate error, *DirtySchemaError (ErrDirtySchema) instead of golang-migrate's ErrDirty, and *UnknownSchemaVersionError (ErrUnknownSchemaVersion). A second migrator waits for the migration lock without golang-migrate's 15 s timeout, and a stored version of -1 reads as none. Match with errors.Is/errors.As, not message text. TypeScript: migrate() throws MigrationError (the pg error is `cause`) instead of the raw database error, and UnknownSchemaVersionError where it used to apply the migrations above an unknown version. The test suite reads POSTGREMQ_TEST_DATABASE_URL instead of TEST_DATABASE_URL. Rust: a failed migration is Error::Migration (ErrorKind::Migration; sqlstate() and the source still give the database error) instead of Error::Sqlx, and an unknown version is Error::UnknownSchemaVersion instead of applying the migrations above it.
* **sql,go,ts,rs:** mq 0.2.0 changes SQL contracts. consume_message, set_vt_batch_multi and extend_queue_keep_alive_multi return vt_remaining_ms / keep_alive_remaining_ms instead of vt / keep_alive_until; set_vt returns BIGINT milliseconds left instead of TIMESTAMPTZ; get_next_visible_time is replaced by get_next_visible_in_ms (BIGINT milliseconds); nack_message takes p_delay_ms BIGINT instead of p_delay_until TIMESTAMPTZ. Clients accept only mq 0.2.x: stop older clients, migrate, then deploy these. Go Message.VT, TS message.vt and Rust Delivery::vt() are now the lease end on the application's clock.
* **sql,go,ts,rs:** clients accept any patch of the mq minor they implement before 1.0 (0.2.x in this release) and reject the other lines. Go `SupportedMQMajors() []int` is now `SupportedMQVersions() []string` and `CompatibilityError.SupportedMajors` is now `SupportedVersions`. TS `SUPPORTED_MQ_MAJORS` is now `SUPPORTED_MQ_VERSIONS` (`string[]`) and `CompatibilityError.supportedMajors` is now `supportedVersions`. Rust `SUPPORTED_MQ_MAJORS: &[u64]` is now `SUPPORTED_MQ_VERSIONS: &[&str]`.

## 0.1.0 (baseline)

The state of the TypeScript client (npm `postgremq`) when independent versioning started. It was never
published as 0.1.0; the first release is the next version above.

- Connection over a node-postgres pool; publish (also on a caller's
  transaction), async-iterator and handler-based consumers.
- Connection-level batched lease renewal and exclusive-queue keep-alive.
- Shared LISTEN session with reconnect and polling fallback.
- Schema migrations (`migrate`, `getMigrationStatus`), compatible with the Go
  client and the CLI.
- Queue-loss teardown (`onClose`, `onQueueFatal` / `'queueFatal'`,
  `QueueFatalError`), graceful shutdown, retry for transient errors.
- Optional OpenTelemetry metrics.
